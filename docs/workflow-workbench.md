# 流程开发工作台

## 范围与使用

界面位于现有 flow 前端，组件路径为 `/src/views/backend/todo/WorkflowWorkbench.vue`，建议菜单路径为 `/flow/workflowWorkbench`。页面通过现有 RBAC 动态菜单加载，没有增加绕过菜单权限的静态路由。

支持拖拽 BPMN、节点属性配置、单人/多人审批、会签/或签、分支条件、驳回目标、选人槽位、页面与回调配置；同时提供 XML/JSON 编辑、成对导入导出、发布预检与覆盖发布。新建模板携带框架结束回调节点，画布可直接拖入人工审批和结束回调。

“按后续节点生成槽位”会关联常规路径的处理人变量、选人模式和角色，并为没有绑定人员的新人工节点生成变量表达式。复杂表达式、默认分支、多条件汇合或子流程边界提示手动配置，不猜测业务条件。

测试台直接复用正式部署、发起、待办、审批、驳回和终止接口。测试请求可填写真实业务 ID、变量、人员和业务系统回调，不引入模拟执行接口或测试隔离路径。请求失败重试保留 requestId；主动重新发起才生成新的 requestId。

“已发布流程”页签提供独立表格，支持按名称搜索、分页、查看 BPMN XML 与节点 JSON、载入画布编辑、成对导出和发起测试。切回表格时重新读取定义，保留当前搜索条件和页码。“发起测试”载入所选定义的联调表单，由用户填写业务信息、人员、变量和回调后正式提交；原有“按业务 ID 找回实例”入口继续保留。

流程定义的文件名兼容 Flowable 返回的 `resource` 资源 URL 和已有 `resourceName` 字段，资源 URL 仅用于提取文件名，不作为新的请求目标。

## 发布门禁与引导测试

“流程测试”分为检查与发起、逐节点办理、结果与回调三个步骤。发起前逐项展示与正式启动接口一致的 ACTIVE 检查：Flowable 定义存在、当前版本发布配置已登记、登记绑定的定义 ID 与当前定义一致。未通过时给出原因和返回设计页发布的入口；只读检查不会登记配置、创建实例或绕过门禁。重新进入测试页会刷新检查。

`caseflow_clue` 的既有版本可在 Flowable 中读取，但缺少匹配的 ACTIVE 登记；本轮没有擅自覆盖该业务流程。原文件和节点配置已通过编译预检，可在设计页正式覆盖发布后重新检查。发布创建新定义版本，在途实例继续绑定原版本。

发起人来自登录身份。发起只创建实例，不自动完成发起人任务；默认不提前要求填写发起人节点的下一步选人，实际办理该节点时才填写。启动表达式确需预填人员时，可在高级配置中显式提供。单个实际任务会自动选中并读取可操作项，多任务保留选择；“本轮选人使用我”仅在用户点击后填写当前所需槽位。每次提交后重新读取真实任务，不推算路由。

默认视图保留测试名称、实际任务及必要填写信息；业务 ID、回调地址、自定义变量、推荐人员和完整请求 JSON 放入高级配置，回调未填写时提供明确设置入口。按业务 ID 找回继续保留，恢复后进入对应执行或结果步骤。请求与引擎诊断默认折叠。

编辑与测试页面按用户提供的 Claude 设计方案整理字体层级、衬线标题、32px 卡片留白、12px 卡片圆角、8px 控件圆角和 40px 控件高度，颜色沿用现有主题。节点配置按人员、业务规则、下一步选人及高级配置分组；文件导入导出和完整源码集中到流程高级配置。左侧人工审批工具在默认提供者之后注册，避免被普通任务覆盖。

## Flowable 是新部署的配置来源

节点 JSON 随 BPMN 存入流程级扩展：

```xml
<extensionElements>
  <pc:nodeConfigurations xmlns:pc="urn:process-center:configuration:1">[节点配置 JSON]</pc:nodeConfigurations>
</extensionElements>
```

新部署和新工作台都使用同一编译、校验逻辑。运行时按实例绑定的 Flowable 定义读取嵌入配置；DM8/ES 的节点规则仍为兼容投射，既有部署幂等、业务实例绑定和投递记录继续沿用。

界面没有草稿、另存版本或版本管理。覆盖发布沿用 Flowable 自身的部署机制，运行中的旧实例继续绑定原定义；没有删除历史部署或迁移在途实例。旧实例回调目标也按其绑定定义读取，审计上下文按实例查询。

历史部署如果没有嵌入 JSON，工作台会明确标记旧投射来源。重新发布后进入统一资源格式。没有对所有存量部署执行批量改写。

## 新增接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/flowable/workbench/definitions` | 从 Flowable 查询最新定义，按名称搜索及分页 |
| GET | `/api/flowable/workbench/definitions/{key}/artifact?version=...` | 回读实际 BPMN 和配套配置；省略版本读最新，联调按任务绑定版本读取 |
| GET | `/api/flowable/workbench/definitions/{key}/readiness` | 只读返回逐项 ACTIVE 门禁、失败原因和处理动作；不创建或激活定义 |
| POST | `/api/flowable/workbench/compile` | 无副作用预检，返回节点定位错误及生成文件 |
| GET | `/api/flowable/workbench/instances/{processInstanceId}/variables?businessId=...` | 核对业务归属后读取当前引擎变量 |
| POST | `/api/flowable/workbench/instances/{processInstanceId}/next-step` | 按实例绑定版本、当前任务、已有变量和本次业务变量，只读确定可达人工节点与选人槽位 |

测试办理区先填写分支变量，再显示命中路径的人员。普通排他网关按 BPMN 声明顺序选择首个命中出口，默认分支只在显式条件均不命中时采用；变量缺失时先提示填写。并行网关仍同时返回各分支人员。下一步预览不推进引擎；正式提交会重新核对路径，并在槽位转换前过滤已声明但不在当前路径上的选人，未知槽位继续拒绝。槽位自身的生效条件继续独立生效，使用已有流程变量与本次输入的合并结果。

自动预览支持普通布尔变量、单变量与常量的比较；复杂 JUEL、子流程/事件网关、服务节点可能改写变量后的分支不猜测结果，显式提示使用高级完整请求，沿用原办理契约。流程状态图显示实际人工节点状态，当前节点为蓝色、完成节点为绿色；连线表示定义结构，不将未核实的出口涂成已执行路径。

发布使用既有 `/api/flowable/bpmn/deploy`；测试使用既有 `/api/processes/start`、`/api/tasks/pending`、`/api/tasks/complete` 和 `/api/processes/terminate`。这些共享接口没有被改成工作台专用权限码。

逐步联调复用 `/api/tasks/reassign`，手填人员按实际槽位提交；角色推荐池不替代人员变量。业务变量仅按用户输入的 JSON 提交，不在联调页求值或改写表达式。节点 JSON 可携带 `inputHints` 数组，每项为 `name`、`stage`（`start` / `complete`）及可选 `description`，编译器验证提示结构并原样嵌入 BPMN。输入提示不参与引擎路由，不携带变量默认值。

新增接口沿用现有认证边界；细分 API 权限可在已有 RBAC 网关中映射。菜单权限控制页面入口，不替代网关的接口鉴权。

## 校验与兼容

预检包含 XML/JSON 解析、单流程要求、重复 ID、连线归属、排他分支条件、节点配置引用、选人槽位、单人/集合类型匹配、多人集合变量、驳回目标及选项。错误返回 elementId、field、code 和 message。真正发布仍由 Flowable 校验可执行性；预检通过不等于业务逻辑验收通过。

无图形坐标的文件尝试自动布局，包含只有 `BPMNDiagram/BPMNPlane` 外壳、没有任何 `BPMNShape` 的历史文件。自动布局替换空图形，只合并生成的 DI，不用布局结果替换执行语义；切换页签重新显示画布时重新计算尺寸与居中。当前识别 Flowable 人员表达式、集合、HTTP 字段、异步与重试扩展。未知扩展的导入警告会阻止发布，避免不知情地丢配置。

历史 Flowable 定义可能没有可选的 ES 节点语义记录。标准文档未找到返回空配置，允许查看和编辑原始 BPMN；索引缺失、鉴权失败、服务异常和损坏响应继续报错，不将它们视为无配置。
