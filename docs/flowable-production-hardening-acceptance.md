## 裁决

本轮 1 万级目标通过。当前瓶颈首先是 Flowable/PostgreSQL 冷启动时可承受的 JDBC 并发，而不是缺少 ClickHouse。Redis 继续承担短租约、互斥和限流协调；DM8 继续承担业务锚点、幂等记录、回调 inbox/outbox 与审计事实；Elasticsearch 只承担可重建的待办查询投影。当前不需要引入 ClickHouse，也不应把 Redis 作为流程事实或推荐人快照的唯一存储。
